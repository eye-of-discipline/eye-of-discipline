# Verification Jobs Generator

`bin/creative_process/generate_checks_jobs` builds the list of standard jobs published with the GitLab CI verification process. The script reads job definitions maintained next to standards and combines them into one file:

```text
ci/gitlab/verification-process/cheks_jobs.yml
```

This file is used by the central pipeline:

```yaml
include:
  local: ci/gitlab/verification-process/cheks_jobs.yml
```

This means application repositories that include `ci/gitlab/verification-process/.gitlab-ci.yml` receive the current set of standard jobs as quality gates.

## Place in the Process

The script is run by `bin/prepare_build` after standard metadata is updated:

```text
standards/**/.gitlab-ci.yml
              |
              v
bin/creative_process/generate_checks_jobs
              |
              v
ci/gitlab/verification-process/cheks_jobs.yml
```

Each standard `.gitlab-ci.yml` file defines its own verification job. The generator combines these definitions into one file that can be included by the verification process pipeline.

## Behavior

The script:

1. finds `standards/**/.gitlab-ci.yml` files,
2. validates that each file defines exactly one top-level job,
3. removes the initial YAML separator `---` from source files,
4. adds a `# Source: ...` comment before each definition,
5. writes the result to `ci/gitlab/verification-process/cheks_jobs.yml`.

If no standard jobs are found, it still creates a valid file with a comment:

```yaml
---
# Generated by bin/creative_process/generate_checks_jobs. Do not edit manually.
# Each standards/**/.gitlab-ci.yml file should define one standard job.
# No standard jobs found.
```

## Input Format

Each standard should have its own file:

```text
standards/{domain}/{STD_ID}/.gitlab-ci.yml
```

The file must define exactly one standard job, for example:

```yaml
---
👁️ Eye discipline:STD-REPO-001:
  image: registry.gitlab.com/dev.rachuna/artifacts/containers/python:1.2.1
  extends:
    - .dyscypline
  variables:
    STD_DOMAIN: repozytorium
    STD_ID: STD-REPO-001
    DOCS_MD_FILE_PATH: standards/repozytorium/STD-REPO-001/README.md
    STD_CHECK_SCRIPT: /tmp/discipline/standards/$STD_DOMAIN/$STD_ID/bin/checks
  script:
    - bash "$STD_CHECK_SCRIPT"
```

The rule is intentional:

```text
one standard = one job = one results/{STD_ID}.json report
```

## Default Usage

```bash
bin/creative_process/generate_checks_jobs
```

Use another standards directory:

```bash
bin/creative_process/generate_checks_jobs \
  --standards-dir path/to/standards
```

Use another output file:

```bash
bin/creative_process/generate_checks_jobs \
  --output path/to/cheks_jobs.yml
```

Help:

```bash
bin/creative_process/generate_checks_jobs --help
```

## Options

| Option | Default | Meaning |
| --- | --- | --- |
| `-s`, `--standards-dir` | `standards` | standards directory |
| `-o`, `--output` | `ci/gitlab/verification-process/cheks_jobs.yml` | output file with standard jobs |
| `-h`, `--help` | | show help |

## Result

After a successful run, the script prints:

```text
Generated ci/gitlab/verification-process/cheks_jobs.yml
```

The generated file should not be edited manually. The source of truth remains `standards/**/.gitlab-ci.yml`.
