# Generator jobów weryfikujących

`bin/creative_process/generate_checks_jobs` buduje listę jobów standardów publikowaną razem z procesem weryfikacji GitLab CI. Skrypt czyta definicje jobów utrzymywane przy standardach i skleja je w jeden plik:

```text
ci/gitlab/verification-process/cheks_jobs.yml
```

Ten plik jest używany przez centralny pipeline:

```yaml
include:
  local: ci/gitlab/verification-process/cheks_jobs.yml
```

Dzięki temu repozytoria aplikacji podpinające `ci/gitlab/verification-process/.gitlab-ci.yml` dostają aktualny zestaw jobów standardów jako bramki jakości.

## Miejsce w procesie

Skrypt jest uruchamiany przez `bin/prepare_build` po aktualizacji metadanych standardów:

```text
standards/**/.gitlab-ci.yml
              |
              v
bin/creative_process/generate_checks_jobs
              |
              v
ci/gitlab/verification-process/cheks_jobs.yml
```

Każdy plik `.gitlab-ci.yml` standardu definiuje jego własny job weryfikujący. Generator skleja te definicje w jeden plik, który może zostać dołączony przez pipeline procesu weryfikacji.

## Zachowanie

Skrypt:

1. wyszukuje pliki `standards/**/.gitlab-ci.yml`,
2. waliduje, że każdy plik definiuje dokładnie jeden top-level job,
3. usuwa początkowy separator YAML `---` z plików źródłowych,
4. dopisuje komentarz `# Source: ...` przed każdą definicją,
5. zapisuje wynik do `ci/gitlab/verification-process/cheks_jobs.yml`.

Jeżeli nie znajdzie żadnych jobów standardów, tworzy poprawny plik z komentarzem:

```yaml
---
# Generated by bin/creative_process/generate_checks_jobs. Do not edit manually.
# Each standards/**/.gitlab-ci.yml file should define one standard job.
# No standard jobs found.
```

## Format wejścia

Każdy standard powinien mieć własny plik:

```text
standards/{domena}/{STD_ID}/.gitlab-ci.yml
```

Plik musi definiować dokładnie jeden job standardu, na przykład:

```yaml
---
👁️ Eye discipline:STD-REPO-001:
  image: registry.gitlab.com/dev.rachuna/artifacts/containers/python:1.2.1
  extends:
    - .dyscypline
  variables:
    STD_DOMAIN: repozytorium
    STD_ID: STD-REPO-001
    DOCS_MD_FILE_PATH: standards/repozytorium/STD-REPO-001/README.md
    STD_CHECK_SCRIPT: /tmp/discipline/standards/$STD_DOMAIN/$STD_ID/bin/checks
  script:
    - bash "$STD_CHECK_SCRIPT"
```

Zasada jest celowa:

```text
jeden standard = jeden job = jeden raport results/{STD_ID}.json
```

## Użycie domyślne

```bash
bin/creative_process/generate_checks_jobs
```

Wskazanie innego katalogu standardów:

```bash
bin/creative_process/generate_checks_jobs \
  --standards-dir path/to/standards
```

Wskazanie innego pliku wyjściowego:

```bash
bin/creative_process/generate_checks_jobs \
  --output path/to/cheks_jobs.yml
```

Pomoc:

```bash
bin/creative_process/generate_checks_jobs --help
```

## Opcje

| Opcja | Domyślnie | Znaczenie |
| --- | --- | --- |
| `-s`, `--standards-dir` | `standards` | katalog standardów |
| `-o`, `--output` | `ci/gitlab/verification-process/cheks_jobs.yml` | plik wyjściowy z jobami standardów |
| `-h`, `--help` | | wyświetla pomoc |

## Wynik

Po poprawnym wykonaniu skrypt wypisuje:

```text
Generated ci/gitlab/verification-process/cheks_jobs.yml
```

Wygenerowany plik nie powinien być edytowany ręcznie. Źródłem prawdy pozostają pliki `standards/**/.gitlab-ci.yml`.
